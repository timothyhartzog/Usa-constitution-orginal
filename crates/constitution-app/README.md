# Constitution Research Workbench (WASM app)

A Dioxus + Rust WebAssembly application that runs the entire constitutional
research platform — search, citation graph, timeline, world-constitution
map, blog with embedded interactive widgets — inside the browser, against
a binary archive served as a static asset.

## Architecture

```
crates/constitution-app/
├── build.rs                 - discovers content/blog/*.md at build time
├── assets/
│   ├── main.css             - design system, themes, responsive layout
│   ├── world_meta.json      - generated by build-archive
│   └── constitution_archive.bin   (generated, gitignored)
└── src/
    ├── main.rs              - launch, router, archive loading, blog assembly
    ├── router.rs            - Dioxus Routable enum
    ├── state.rs             - ArchiveState / SelectionState / SearchState / BlogState / Theme
    ├── storage.rs           - localStorage shim (web) / no-op (native)
    └── components/
        ├── nav.rs           - sidebar + theme toggle + burger
        ├── shared.rs        - StatTile, Tag, Modal, LoadingSpinner
        ├── search/          - search bar (with suggestions), filters, results, world-grouped results
        ├── reader/          - annotated text with inline citations, popovers, embeddable widgets
        ├── graph/           - force-directed citation network with kind filter and focus mode
        ├── timeline/        - phase-banded SVG + expandable event cards
        ├── map/             - region cartogram + country detail + comparator
        ├── dashboard/       - stat tiles, top-citations, region bars, coordinated multi-view
        └── blog/            - post list, post view, live editor, widget renderer
```

State flows through Dioxus signals via `use_context_provider` /
`use_context`. A single `SelectionState` is shared by every view in the
coordinated dashboard so clicking a node in the graph highlights related
items in the timeline, map, and results panels simultaneously.

## Prerequisites

- Rust toolchain (1.78+)
- `wasm32-unknown-unknown` target:
  ```
  rustup target add wasm32-unknown-unknown
  ```
- `wasm-bindgen-cli` matching the workspace version (currently 0.2.121):
  ```
  cargo install wasm-bindgen-cli --version 0.2.121 --locked
  ```
- Optional: `binaryen` (`apt install binaryen`) for further size reduction
  via `wasm-opt`
- Optional: `dioxus-cli` (`cargo install dioxus-cli --version '^0.7' --locked`)
  for `dx serve` hot-reload development

## Building

### Production build

```
scripts/build_web.sh
```

Output lands in `dist/`:

| File | Size (release) |
| --- | --- |
| `dist/constitution-app_bg.wasm` | ~2.0 MB |
| `dist/constitution-app.js` | ~78 KB (glue) |
| `dist/assets/main.css` | ~44 KB |
| `dist/assets/world_meta.json` | ~48 KB |
| `dist/assets/constitution_archive.bin` | ~81 MB (web profile) |
| `dist/index.html` | boot loader |

Apply `wasm-opt -Oz` for further bundle reduction:

```
WASM_OPT=true scripts/build_web.sh
```

### Rebuild the archive

The binary archive is large and gitignored; regenerate it when source
documents change:

```
cargo run -p constitution-cli --bin build-archive --release -- \
    --web --window-size 500 --stride 450
```

`--web` excludes the largest corpora (founders' correspondence, Letters
of Delegates to Congress, Elliot's Debates) to keep the WASM payload
manageable. Drop the flag to build the full corpus (~290 MB binary).

### Iterating with `dx`

If `dioxus-cli` is installed and your network allows it to fetch its
esbuild helper, hot-reload development is:

```
cd crates/constitution-app
dx serve --features web
```

Otherwise the manual loop is:

```
scripts/build_web.sh --skip-archive
cd dist && python3 -m http.server 8000
# rebuild on change
```

## Serving locally

After `scripts/build_web.sh` succeeds:

```
cd dist
python3 -m http.server 8000
# open http://localhost:8000/
```

Any static file server works; the app only needs to fetch its sibling
`assets/` directory.

## Deploying

The `dist/` tree is fully static. Drop it on any host that serves
static files: GitHub Pages, Netlify, Cloudflare Pages, S3 + CloudFront,
or behind nginx.

Recommended server hints:

- Serve `application/wasm` for `*.wasm`
- `Content-Encoding: gzip` (or brotli) the `.bin` archive — gzip cuts it
  from ~81 MB to ~20 MB
- Long cache lifetimes on hashed asset paths

## Smoke testing the WASM

```
node scripts/wasm_smoke_test_app.mjs
```

Loads `dist/constitution-app.js`, instantiates the WASM under a minimal
Node DOM shim, and confirms there are no `LinkError` or `CompileError`
issues. Post-instantiation runtime errors from the Dioxus mount step are
expected (the shim does not provide a full DOM) and are ignored.

## Testing

```
cargo test --workspace        # all crates
cargo test -p constitution-archive --lib
```

The archive crate ships 42 unit tests across the tokenizer, BM25 index,
fuzzy matcher, snippet builder, filter, citation extractor, and process
timeline. All pass on `cargo test`.

## Editing content

- **Blog posts**: drop a Markdown file with frontmatter (`title`, `date`,
  `slug`, optional `tags`) into `content/blog/`. The `build.rs` script
  auto-discovers it and compiles it into the binary. Posts may embed
  widgets with `{{widget:name arg=value arg="quoted value"}}`:
  - `search` — live BM25 results
  - `stats` — current archive statistics
  - `mini_graph` — 1-hop citation neighborhood (`target=clause:I.8`)
  - `compare` — side-by-side topic comparison across collections
- **Theme**: cycle via the sidebar toggle (System -> Light -> Dark).
  Choice persists in `localStorage`.
- **In-browser authoring**: `/blog/editor` provides a split-pane Markdown
  editor with live widget rendering and `localStorage` draft autosave.
